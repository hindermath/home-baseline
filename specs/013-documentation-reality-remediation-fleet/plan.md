# Implementation Plan: Documentation Reality Remediation Fleet

## Strategy

1. Freeze Level-0, registry, receipt, Series, and remote-freshness evidence.
2. Prove the Documentation Impact validator against positive and negative
   fixtures before broad propagation.
3. Apply the canonical maintenance package to the 32 registered repositories.
4. Re-run repository-native Homogeneity and classify the 15 inherited findings.
5. Validate, commit, publish, review, and merge each changed repository
   independently.
6. Consolidate exact-head and merge evidence in Level 0, archive D3, and
   release the successor roots without starting them.

## Ownership and Serialization

Target repositories are independent delivery units. Their file changes and PRs
may be prepared independently, but Level-0 evidence, active Series files, and
statistics have a single writer. No repository branch is reused for another
repository.

## Validation

Every target runs its repository-owned Homogeneity, Documentation Impact,
secret, agent-parity, and available native checks. Level 0 runs both
Documentation Impact shells, Intake Review, autonomous state validation,
PSScriptAnalyzer, Homogeneity, generated references, statistics, and
`specify check`.

## Governance

All eleven installed presets are applicable as declared by repository profile.
Security, Architecture, iSAQB, A11Y, Cross-Platform, Agent Parity, Intake
Authoring, Intake Review, Intake Sequencing, Autonomous Run, and Parallel
Autonomous boundaries are recorded. Product architecture and dependency
evidence remain `N/A` unless the actual diff changes their trigger.
