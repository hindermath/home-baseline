# Documentation portal

[Deutsches Dokumentationsportal](README.md)

This portal routes readers to canonical documents by task and audience. A
**canonical document** is the binding source updated first. Derived or generated
files link back to it.

## Four reader paths

### Learners and newcomers

**Prerequisites:** A text browser or editor; no prior Spec Kit experience.

1. Read [Getting started](getting-started.en.md).
2. Open [Learning series start](learning-units/START-HERE-FUER-LERNENDE.md).
3. Select the training occupation, year, and learning unit.
4. Complete the sandbox preflight before agentic work.

**Next action:** Work through the first approved unit in its declared order.

### Daily users

**Prerequisites:** A supported shell and local Level 0 checkout.

1. Open the [maintenance portal](maintenance/README.en.md).
2. Select the operating system and safe inspection mode.
3. Read the text-oriented result and blocking reasons.
4. Perform only the explicitly authorized next action.

**Next action:** Use `--dry-run`, `--check-only`, or `-WhatIf` before a real
maintenance run.

### Maintainers and AI agents

**Prerequisites:** Read the [agent guidance](../AGENTS.md) and Constitution.

1. Understand [Source and Home Runtime](architecture/source-and-home-runtime.en.md).
2. Read the [script reference](scripts/reference.md) and affected architecture.
3. Determine security, accessibility, and Documentation Impact boundaries.
4. Run affected validation and record evidence.

**Next action:** Change only the canonical Level 0 source and record exactly one
Documentation Impact decision.

### Audit and troubleshooting

**Prerequisites:** Commit identity and read-only evidence access.

1. Open [Audit and troubleshooting](troubleshooting/README.en.md).
2. Identify feature, run, exact head, and accepted hashes.
3. Compare report, event, test, and provider evidence.
4. Apply the documented proof boundary and reevaluation rule.

**Next action:** Revalidate stale evidence at the current head before relying on it.

The [efficiency guide](maintenance/agentic-workspace-efficiency-guide.en.md)
combines all four paths in one detailed, source-bound operating model.

## Document classes

- **Active semantic:** Maintained editorially in its canonical source.
- **Generated:** Updated through its source and renderer.
- **Archived or historical:** Preserved unchanged as evidence.
- **Agent surface:** Synchronized across all maintained agent files.
- **Intake and feature evidence:** Bound to hashes, decisions, and proof limits.

Binding rules are defined in
[Documentation governance](documentation-governance.md).
